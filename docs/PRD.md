# PRD：晨星 AI 原生团队协作平台 MVP

> 作者署名：晨星
> 版本：Phase 1 调研稿（v0.1）
> 日期：2026-09-21

---

## 结论先行（Executive Summary）

市面头部协作工具的 AI 都是"叠加层"（人类先操作、AI 辅助），而非"原生闭环"；且全部闭源、数据出境、定价随席位线性膨胀。晨星要做的是：**自托管、数据可控、AI 贯穿"看板协作 + 知识库 + 会议纪要 + 任务/代码助手"四大模块的 TypeScript 全栈平台**，MVP 跑通一条最小闭环——用户在建好的项目空间里，用自然语言让 AI 助手建任务、把文档喂进 RAG 知识库问答、上传会议录音自动出纪要与待办。差异化一句话：**开源可私有部署的 Linear + Notion AI + ClickUp Brain 的整合体**，但 AI 是第一公民而非插件。

---

## 一、问题陈述

- **谁**：5–30 人、重视数据主权的中小团队（软件/产品/咨询/研究所），已有 AI 使用习惯但被工具割裂。
- **场景**：日常在 Linear/Notion/飞书间反复横跳——看板归看板、知识散在文档、会议纪要在另一个 App、代码助手又单独开一个窗口；AI 能力各自为政、互相不连通，且企业文档要上传给第三方云端模型。
- **痛点**：
  1. 闭环断裂：任务、知识、会议、代码四件事在四个工具，上下文无法贯穿。
  2. 数据出境：Notion/ClickUp 把工作区内容送往 OpenAI/Anthropic（虽声明不训练，但数据离开内网）。
  3. 成本随人头膨胀：AI 按席位月费（$9–24/人/月），30 人团队年支出轻松 $3000–8600。
  4. 自主化 PM 缺位：Height 已验证"AI 自主整理 backlog"的需求，但 2025-09-24 关停、无开源替代——这是明确空白点。
- **现有方案为何不行**：闭源 SaaS 无法私有部署、AI 模块割裂、定价不可控；纯自建又成本过高。

## 二、目标用户画像与核心场景

| 角色 | 画像 | 核心诉求 | 技术水平 |
|------|------|----------|----------|
| 主要用户：中小团队负责人 / PM | 5–30 人团队管理者，关注交付与信息整合 | 一个空间看全部进展，AI 自动整理任务与纪要 | 中 |
| 主要用户：工程师 / 研发 | 频繁建 issue、写代码、翻文档 | 自然语言建任务、代码助手、知识库精准问答 | 高 |
| 次要用户：知识管理员 / 文档 owner | 维护 SOP、规范、Wiki | 把文档喂进 RAG，团队随问随答、带引用 | 中 |
| 次要用户：合规 / IT | 关心数据不出内网、可审计 | 自托管、SSO、权限隔离 | 高 |

**核心使用场景（MVP 验证）**
- S1 建空间→用对话建任务/分派→看板流转。
- S2 上传产品文档/规范→RAG 知识库问答（带来源引用）。
- S3 上传会议录音→自动转写→AI 出纪要 + 行动项并转成任务卡片。
- S4 选中代码片段/任务→AI 解释、补全、生成子任务。

## 四、差异化定位

1. **原生整合，非插件**：四大 AI 模块共享同一项目空间上下文（任务、文档、对话互通），而非四处跳转。
2. **数据主权**：docker-compose 一键自托管；支持接本地/私有模型（Ollama + 文本嵌入），敏感文档不出内网。
3. **自主 PM 继承者**：把 Height 验证过的"AI 自主整理 backlog/分流"做进开源自托管版，填补空白。
4. **成本可预测**：自托管无固定席位费，推理成本由团队自己掌控（可混用云端 API 或本地模型）。
5. **TS 全栈一致性**：Next.js 前端 + Node 后端，团队只用一种语言，降低维护与招聘门槛。

## 五、MVP 范围（功能清单 P0 / P1）

### 5.1 P0（MVP 必做，端到端闭环）

| 功能 | 说明 | Reach | Impact | Confidence | Effort | RICE | MVP? |
|------|------|-------|--------|------------|--------|------|-------|
| 项目空间 + 任务看板 | 建空间/项目，任务卡片 CRUD，看板列（Backlog/进行/完成）拖拽，基础权限 | 10 | 3 | 100% | 3 | 10.0 | 是 |
| AI 对话助手（LLM/Agent） | 项目内聊天窗，自然语言建任务/分派/查询；流式输出；调用工具 | 10 | 2 | 80% | 3 | 5.3 | 是 |
| RAG 企业知识库 | 上传文档（PDF/MD/DOCX/TXT）→分块嵌入→pgvector 存储→带引用问答 | 8 | 3 | 80% | 4 | 4.8 | 是 |
| 会议纪要 / 总结 | 上传录音/文本→转写（Whisper）→AI 纪要 + 行动项→一键转任务卡片 | 6 | 2 | 80% | 4 | 2.4 | 是 |
| 代码 / 任务助手 | 选中代码或任务→解释/补全/生成子任务（复用对话助手工具集） | 7 | 1.5 | 70% | 2 | 3.7 | 是 |

> RICE 公式：Score = (Reach × Impact × Confidence) / Effort，Reach 1–10、Impact(0.25–3)、Confidence(50%–100%)、Effort 1–10（人月）。

### 5.2 P1（MVP 后，验证后做）

- AI 自主 backlog 梳理 / 自动分流（Height 式，继承空白点）
- Slack/飞书/GitHub 集成与自动化触发
- 多模型路由（云端 API 与本地模型按成本/质量切换）
- 企业级 SSO（SAML/OIDC）、细粒度角色、审计日志
- 看板多视图（列表/甘特/日历）、Cycles/Modules

### 5.3 MVP 明确不做（带原因）

| 不做 | 原因 |
|------|------|
| 自研基础大模型 / 自训嵌入 | 成本与周期不可控，直接复用开源（LangChain.js / LlamaIndex.TS / Ollama） |
| 复杂甘特 / 资源排程 / 工时计费 | MVP 验证协作闭环即可，超出 1–3 核心功能原则 |
| 移动原生 App | Web 响应式优先，移动端延后 |
| 多租户 SaaS 计费体系 | 定位自托管，MVP 不做账户计费/订阅 |
| 实时多人光标协同编辑 | 先用基础实时保存，CRDT 协同留 P1 |
| 工作流自动化引擎（类 Zapier） | 先人工触发 AI 动作，自动化编排后置 |
| 国际多语言完整本地化 | 先中文为主，i18n 接口预留 |

## 六、验收标准摘要（Given / When / Then）

- **看板**：Given 已建项目空间，When 用户拖拽任务卡到"完成"列，Then 卡片状态持久化且其他成员实时可见。
- **AI 建任务**：Given 在项目对话窗输入"给小明建一个登录页 bug 任务，高优先级"，When 提交，Then 生成对应任务卡并正确分派/打标签。
- **RAG 问答**：Given 已上传 3 份产品文档并完成嵌入，When 提问"定价策略是什么"，Then 返回答案且附带≥1 处来源文档片段引用，未上传内容不臆答。
- **会议纪要**：Given 上传一段会议录音，When 处理完成，Then 产出结构化纪要（决策/行动项），且每个行动项可一键转为任务卡。
- **代码助手**：Given 选中一段报错代码并请求解释，When 提交，Then 返回解释与修复建议且不含与上下文无关内容。
- **自托管**：Given 干净环境执行 `docker-compose up`，When 服务启动，Then 前端/后端/PG（pgvector）/模型网关均可达，种子数据可登录。

## 七、模块划分建议（解耦 + 复用开源 + 协同）

**原则：四大 AI 模块均为"可插拔服务"，与协作平台核心（看板/空间）通过统一事件总线和共享 PostgreSQL 解耦。**

```
┌─────────────────────────────────────────────┐
│  Next.js 前端（TS）  ── 统一对话/看板/知识库 UI   │
├─────────────────────────────────────────────┤
│  Node 后端 API（TS / Nest 或 Fastify）          │
│  · 协作核心：空间/项目/任务/权限（领域服务）       │
│  · AI 编排层：Agent 路由 + 工具注册表            │
├──────┬──────┬──────┬──────┬──────────────────┤
│ LLM/ │ RAG  │ 会议 │ 代码/│  共享：PostgreSQL   │
│ Agent│ 服务 │ 服务 │ 任务 │  (pgvector 扩展)   │
│ 模块 │ 模块 │ 模块 │ 助手 │  + Redis（队列/缓存）│
└──────┴──────┴──────┴──────┴──────────────────┘
```

- **协作核心（自研，TS）**：空间/项目/任务/看板/权限。数据模型参考开源 Plane（Cycles/Epics/Issues 思路），但用 TS 重写，不引入 Python 依赖，保证全栈一致。
- **LLM/Agent 模块**：复用 **LangChain.js** + **LangGraph.js**（TS 原生）做多步 Agent 与工具调用；模型网关抽象，支持 OpenAI/Anthropic/本地 Ollama 切换。
- **RAG 模块**：复用 **LlamaIndex.TS** 或 **LangChain.js** 的 `PGVectorStore`（pgvector），单一 PostgreSQL 同时存业务数据与向量，降低部署复杂度、保证可复现；嵌入用 `text-embedding-3-small` 或本地 `nomic-embed-text`。
- **会议纪要模块**：转写复用 **faster-whisper / OpenAI Whisper API**，总结与行动项抽取复用同一 LLM 网关；产出结构化 JSON 再由协作核心转任务卡。
- **代码/任务助手模块**：不单独造轮子，作为 Agent 的一个"工具集"（代码解释、diff 生成、子任务拆解），共享对话助手上下文。
- **协同机制**：所有模块通过后端"工具注册表"向 Agent 暴露能力（建任务、查知识库、读代码）；事件总线（Redis Stream）让会议模块产出即时触发任务卡创建，实现闭环。
- **复用开源清单**：LangChain.js、LangGraph.js、LlamaIndex.TS、pgvector、Whisper、Ollama（可选本地模型）、Dify 仅作 RAG 编排理念参考（不引入其 Python 运行时）。

## 八、非功能需求与数据埋点（摘要）

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 首屏 < 3s，API p95 < 500ms，RAG 问答 < 3s | P0 |
| 安全 | HTTPS + JWT + 输入校验 + 速率限制；文档不出内网（本地模型可选） | P0 |
| 可复现 | docker-compose 一键起，干净环境可跑通最小闭环 | P0 |
| 兼容性 | Chrome/Safari/Firefox 最新 2 版，企业微信内置浏览器 | P0 |
| 可访问性 | 键盘可达 + 对比度达标（WCAG 2.1 AA 基本） | P2 |
| 国际化 | 中文优先，预留 i18n 接口 | P2 |

**MVP 必埋事件**：`page_view`、`sign_up_complete`、`first_task_created`（激活）、`rag_query`（含是否命中来源）、`meeting_processed`、`agent_tool_called`、`error_occurred`。事件命名 `{对象}_{动作}`，附带 `user_id/timestamp/version`，不采集隐私原文。

## 九、风险提示

1. Height 关停证明"纯自主 PM"商业难；晨星以自托管+开源+一体化闭环规避其单点商业模式风险。
2. 多模型/本地模型质量波动可能影响 RAG 与纪要体验，MVP 默认走云端 API、本地模型作为可选路径。
3. 全栈 TS 下 RAG 生态成熟度略逊 Python（Dify/RAGFlow），但 LangChain.js/LlamaIndex.TS + pgvector 已足够支撑 MVP。
